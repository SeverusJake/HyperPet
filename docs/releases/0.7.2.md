# HyperPet 0.7.2

## Notifications

- The newest notification appears immediately. Displaced messages return newest
  first when the current message is dismissed or expires.
- Windows notifications created before monitoring starts, including after
  re-enabling the source, are skipped instead of replaying the startup backlog.
- An in-app popup that remains unreadable for two scans alerts once without
  content instead of being silently dropped.
- In-app monitoring runs independently of Windows notification permission.
  Source toggles and subscription generations reject stale callbacks and polls.
- UI Automation scanning runs on a background worker with bounded traversal.
  Diagnostic logs omit notification titles and bodies by default.

## Reliability

- Pet imports validate paths, images and resource budgets before replacing an
  installed pet. Failed replacement preserves the original or its recovery path.
- Imports support cloud placeholder folders such as OneDrive while continuing
  to reject symbolic links and junctions. Built-in pet IDs remain protected.
- Settings writes are atomic with a backup. Failed pet preparation or startup
  changes preserve existing settings and the live pet. Closing Settings cancels
  pending changes; repeated clicks cannot open duplicate dialogs.
- Active-pet removal prepares a playable fallback before removing files and
  reports recoverable leftovers if cleanup fails.
- Fixed animation completion, visible-sprite positioning and Settings sizing.
- Debug uses a separate profile; portable/debug launches do not take over the
  installed app's Windows startup registration.
- Updated self-contained Core/Desktop runtimes to .NET 10.0.15 and removed
  obsolete notification activation/debug dependencies.

## Downloads and updates

- **HyperPet-v0.7.2-win-Setup.exe**: installer with updater support.
- **HyperPet-v0.7.2-win-Portable.zip**: extract and launch HyperPet.exe.
- Full/delta nupkg and releases.win.json: updater files, with a delta built
  against the published 0.7.1 full package.
- build-manifest.json identifies the exact clean source commit; SHA256SUMS.txt
  covers the distribution/update assets and build manifest.

## Validation

- 270 Release tests pass (71 Core, 199 App).
- Release safeguard checks include process exit success, assertion failure and
  cleanup failure under the GitHub Actions PowerShell wrapper.
- Release packaging requires a clean committed source and a dependency audit.
- Installer/identity/permission integration, physical mixed-DPI transitions and
  sustained native WinRT/GC stress remain manual validation items.
